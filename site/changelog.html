Drive9 v0.10.0

A persistent, mountable working directory where Git, SQLite, build tools, artifacts, and multi-step agent runs survive sandbox restarts.

June 15, 2026

First public release for coding-agent workspaces

Drive9 gives agents a filesystem-shaped workspace with server-side state, local execution layers, scoped permissions, fast Git paths, and LayerFS isolation for parallel attempts. It is built for real developer workloads, not disposable sandbox volumes or object-storage APIs.

Core workspace capabilities

01

Git workload: standard Git commands still work

Agents can keep using normal Git inside a Drive9 mount. Source files, patches, config changes, logs, and collaborative output live in the server-side workspace; high-churn local state such as .git, object caches, dependencies, and build output stays local for performance.

cd /mnt/workspace
git clone https://github.com/org/repo .
git checkout -b fix-auth
git status
git add . && git commit -m "fix auth"

For large repositories, the fast path avoids pushing every clean checkout file through ordinary FUSE writes:

drive9 git clone --fast --blobless --hydrate=sync https://github.com/org/repo /mnt/workspace/repo
drive9 git worktree add --fast --blobless -b fix-auth /mnt/workspace/repo /mnt/workspace/repo-fix-auth HEAD

02

LayerFS: isolated filesystems for parallel agent attempts

LayerFS lets agents create isolated writable layers from the same base workspace, run different attempts in parallel, inspect diffs, checkpoint progress, roll back failed attempts, and commit successful work back to base.

drive9 fs layer create --name fix-auth --tag task=auth /repo
drive9 fs layer create --name fix-session --tag task=session /repo

drive9 mount --layer tag:task=auth :/repo /tmp/fix-auth
drive9 mount --layer tag:task=session :/repo /tmp/fix-session

Commit is conflict-aware, not a blind overwrite. If the base changed under a layer, Drive9 reports a conflict and keeps the base safe.

drive9 fs layer diff tag:task=auth
drive9 fs layer checkpoint --label before-final-test tag:task=auth
drive9 fs layer rollback tag:task=session
drive9 fs layer commit tag:task=auth

03

Context fork: isolate a whole workspace context

ctx fork creates a server-side copy-on-write context fork. A fork can read parent state but isolates later writes into a new context, which is useful for another agent, another direction, or a longer-running experiment.

drive9 ctx fork auth-experiment --from owner

LayerFS is the lightweight tool for parallel attempts inside a workspace. ctx fork is the larger boundary for splitting an entire workspace context.

04

Scoped tokens: least privilege inside the workspace

Workspace Zone scoped tokens limit an agent to the exact path and operations it needs. The permission boundary lives inside the workspace, not just at the sandbox or container boundary.

drive9 token issue repo-reader --ttl 1h --allow /repo:read,list
cat /mnt/workspace/repo/README.md        # allowed
echo x > /mnt/workspace/repo/new.txt     # denied if token is read-only
cat /mnt/workspace/secrets/token.txt     # denied if outside scope

05

Pack/unpack: warm restore for local execution state

Drive9 does not treat every local execution artifact as collaborative workspace state. pack and unpack make local-layer state portable across sandbox replacement while keeping server-side workspace files as the source of truth.

drive9 pack --local-root /tmp/drive9-local --remote-root /repo --profile coding-agent
drive9 unpack --local-root /tmp/drive9-local --remote-root /repo --profile coding-agent

Other notable improvements

2–3× faster cold reads

Small files are fetched in a single request, repeated reads hit revision-bound local disk cache, and concurrent fetches are deduplicated without serving stale data.

Fuller POSIX behavior

Symlinks, hardlinks, recursive copy, byte-range reads, chmod, preserved create modes, and stable file identity make Drive9 mounts behave more like real working directories.

Durability controls

drive9 mount --durability=auto|interactive|fsync|close-sync|write-sync lets users choose the right latency/persistence tradeoff.

Production hardening

Alibaba OSS/KMS/ACK support, tenant metrics, semantic-worker scheduling improvements, tiered e2e/performance gates, and broader live POSIX/Git/SQLite coverage.

Getting started

# Install
curl -fsSL https://drive9.ai/install.sh | bash

# Mount a workspace
drive9 mount :/ ~/agent-work

# Clone a repo into it using the fast Git path
drive9 git clone --fast --blobless --hydrate=sync https://github.com/your/repo ~/agent-work/repo
