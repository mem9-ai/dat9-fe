Drive9 v0.10.0

Agents get a real working directory — with Git, SQLite, and file persistence that survives sandbox restarts.

June 15, 2026

First public release for coding-agent workspaces

Drive9 v0.10.0 gives agents a persistent, mountable workspace where code can be cloned, edited, tested, packed, layered, checkpointed, and recovered across sandbox lifecycles. Unlike object storage APIs or short-lived sandbox volumes, Drive9 is designed for real filesystem workloads — Git, SQLite, build tools, artifacts, and multi-step agent runs.

View on GitHub

What changed

A real working directory

Agents can run ordinary developer tools against a Drive9 mount. Symlinks, hardlinks, file modes, write visibility, and durability controls make the workspace behave like a filesystem, not a blob API.

Git works where the agent works

Agents can clone into a Drive9 mount, create fast worktrees, switch context, and resume after a sandbox restart without treating the repository as disposable scratch space.

Cold reads wait less

Small files are fetched whole, repeated reads can hit local disk, and concurrent fetches are deduplicated. The cache is still revision-bound, so speedups do not come from serving stale workspace state.

Workspace state can move

Workspaces can be packed, unpacked, layered, and moved across machines or sandboxes. Agents can experiment in copy-on-write layers and keep the base workspace clean until changes are ready.

Production controls are built in

Scoped tokens, tenant metrics, Alibaba OSS/KMS/ACK support, and tiered e2e/performance gates make Drive9 easier to run as infrastructure, not just a local developer tool.

Weekly highlights

Week of 2026-05-18

Durability controls and scoped workspace access

  • Choose the right write-safety tradeoff with --durability=auto|interactive|fsync|close-sync|write-sync.
  • Workspace Zone scoped tokens restrict filesystem and upload access by default.
  • Recursive drive9 fs cp -r and byte-range drive9 fs cat make the CLI useful for larger trees and partial reads.

Week of 2026-05-25

POSIX compatibility and fast Git clone

  • Symlinks work across backend, CLI, SDK, and FUSE so common developer trees behave correctly.
  • Local writes become visible safely and pending file create modes are preserved.
  • drive9 git clone --fast skips unnecessary FUSE checkout work for cleaner, faster repository setup.
  • Kotlin and Swift SDKs expand Drive9 beyond Go/TypeScript clients.

Week of 2026-06-01

Git worktrees, hardlinks, and read-cache architecture

  • drive9 git worktree add --fast and remove --fast support branch-style agent workspaces.
  • Hardlinks keep stable file identity and link counts for POSIX-heavy tools.
  • Revision-bound disk cache, parallel block reads, and singleflight deduplication speed up repository reads.
  • Live POSIX, Git, SQLite, concurrency, and performance gates catch regressions before release.

Week of 2026-06-08

Portable workspaces, layered overlays, and crash recovery

  • drive9 mount now backgrounds by default; use --foreground for blocking behavior.
  • Layered copy-on-write overlays let agents experiment without mutating the base workspace.
  • drive9 pack, drive9 unpack, and the portable profile move workspace state across machines and sandboxes.
  • FUSE crash-recovery hardening protects staged writes and keeps recovery behavior testable.
  • Alibaba OSS, KMS, and ACK support make Drive9 deployable in more production environments.
